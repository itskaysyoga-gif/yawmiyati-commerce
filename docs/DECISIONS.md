- 2026-10-29 (night) — Development frozen; staging only (Rashid). Staging releases: a commit on `main` with a green `tests` run on `main`, tagged `staging-YYYYMMDD-N`; every destination is proven to be a password-protected staging store at `STAGING_BASE_URL/<cc>/` with environment staging or development before any store file changes; backup, swap under maintenance, verify over HTTP, automatic rollback; an interrupted run is rolled back by the next one. No per-release human approval click: staging releases are not money decisions, and a gate nobody is watching would only block fixes. Order tests come in two classes: cancelled before shipping (Claude may run them inside the open test window) and delivered (each one needs Rashid's written yes naming offer, price and recipient). The test window opens only behind the password with the server cron running, and every order placed in it is marked `_ym_test` automatically (this was documented but not implemented before). One Taager request replaces rounds 3-5.

- 2026-10-29 — Consent invariant across stores: a withdrawal is queued in the store's own table first (atomic upsert), each store certifies its queue to the shared ledger every 5 minutes, and server ad events are two-phase in every store (decide, wait until every store in YM_CONSENT_STORES certified past the decision, re-read the ledger, send). A store that cannot write the ledger can never certify, so its withdrawals hold everyone's events instead of leaking. Residual window stated in MEASUREMENT.md §4.
